# 构图与 shot list

## 真实场景契约

每张项目封面都以写实的真实场景满铺为背景。真实场景指有可信空间、透视、光线和材质的实际使用环境，可以由图片工具生成，不要求用户上传照片；不等于对某个真实地点或产品截图的事实证明。纯项目图标 `project-mark` 可另行使用透明或纯色底，正式公司 LOGO 始终按原素材合成。

从已确认项目内容选择场景，而不是看到“AI / Skill”就固定使用办公桌。先识别用户在什么环境完成什么任务，再选择能体现该任务的空间与物件。例如采收库存项目可选择农产分拣区，以周转筐、称重台和清点动作体现使用场景；不是把菜筐图标放在渐变背景上。没有设备或截图需求时不强行添加显示器。

`SHOT_LIST_PENDING` 的每张封面方案必须包含：

- 真实场景：具体地点/空间、相关物件或动作、光线与材质。
- 项目关联：该环境如何对应已确认的用途或用户流程；不虚构项目能力。
- 构图：背景满铺，文字可直接覆盖低干扰区域；不固定“左侧空白文案区、右侧场景”的分割式布局。
- 品牌一致性：不同平台复用配色、光线与场景主题，但按画幅重新安排镜头；同一封面的中英文版本复用同一底图。

将已确认的场景描述与关联理由分别保存为现有 BrandBrief `style.scene`、`style.scene_rationale` 字符串，供提示词与 manifest 追溯；不新增 YAML 或状态机阶段。信息不足时，先给出明确标为推断的候选真实场景，在现有 QA 中确认；无法作合理推断时聚焦询问用途，不用抽象背景填补。旧 brief 缺少这两个字段时，补齐场景方案再取得 shot list 确认，不把字段缺省视为已确认。

纯黑、纯色、纯渐变、悬浮图标或抽象科技线条不能替代真实场景。深色、霓虹、黑金、极简或 3D 风格仅影响色调、光线、排版和前景元素；写实环境仍必须可辨识。已授权 IP 可以融入场景，但不能取代环境。生成界面只用无关键文字的概念占位，不冒充真实截图。

先根据 `output-specs.md` 确认目标平台和画幅，再按每个比例单独规划封面构图；不生成 1:1 方形 LOGO 主视觉。真实场景背景铺满画面，并根据项目用途选择合适的空间、道具和光线；不要固定切成“左侧留文案区、右侧产品场景”。文案允许覆盖在背景上，靠清晰对比与排版保持可读，不对整张背景加模糊层。多个版本沿用同一场景主题、品牌色和视觉气质，但针对每种画幅分别构图并生成匹配底图；不能裁切或拉伸一张底图来冒充其他比例。

将确认的整体场景描述及项目关联理由分别记入 JSON 品牌档案的 `style.scene` 与 `style.scene_rationale`；需要按平台进一步细化时，将目标专属场景记入 `outputs.targets[].scene_concept`。信息不足时，先给出明确标为推断的候选真实场景，在现有 QA 中确认；无法作合理推断时聚焦询问用途，不用抽象背景填补。旧档案缺少场景字段时，先补齐场景方案并重新确认，不把字段缺省视为已确认。

## 输出构图

只制作用户确认的平台封面。依据 `output-specs.md` 为 YouTube、抖音、小红书、GitHub 和自定义画布逐项确认用途、尺寸、比例及安全区；宽版可展示更多已确认功能点，竖版和小画幅应缩短文案、放大主体。具体位置按背景与可读性安排，不预设空白半幅。

## 主视觉风格构图

- **暖色创作者桌面海报**：依据用户单独提供的人物素材安排人物在真实创作桌前操作电脑；场景使用暖木桌面和柔和琥珀色灯光，并为确定性标题留出清晰区域。最终文案由 Pillow 使用已确认字体排版；当前内置预设不保证笔刷字形、手绘线或逐词双色效果。人物素材与风格参考分开使用，不能从参考图复刻脸部。
- **演讲舞台大屏海报**：画面必须同时有主讲人物和清晰可见的大屏。镜头角度可随平台画幅调整，但不能让人物或屏幕消失、变成不易辨识的小元素。为让确定性排版自然落在屏幕内，大屏应宽阔、接近正对镜头、透视畸变轻，屏幕边框清晰且留出一块平整、干净的内容面；避免弯曲屏幕、强烈梯形透视和横穿文字区域的反光。主标题置于屏幕外，以大字分层呈现；主标题以外的已确认文案排入屏幕中的留白/内容区，文字的边界、对齐和留白要服从屏幕边框，看起来像屏幕界面本身，不像浮在屏幕前的字幕卡片。屏幕仅呈现确认过的文案，不生成额外可读 UI 字样。标题白色基础色与关键词强调色按 QA 确认结果排版。
- **明亮 SaaS 产品展示**：在明亮的真实产品演示/工作环境中，以显示器或设备上的产品画面为主视觉，文字说明与功能卡片形成清楚层级。只有使用用户提供的真实界面截图时才呈现真实可读界面；无截图时使用不带虚构文字的抽象界面块，功能卡片只使用已确认的产品事实。
- **沿用当前项目已有风格**：以当前项目已确认的品牌档案和已通过成品为依据。无可访问或已确认来源时停止该分支并让用户选择其他风格/补充参考，不能虚构“项目既有风格”。

这些风格只定义视觉方向，不改变平台尺寸、安全区和真实场景要求。参考图库中的原图仅用于风格抽象，不复制其人物身份、文字、商标、UI 或水印。

流程图按画幅取舍：宽版封面可放清晰的 3–4 步流程；竖版和小尺寸改为 2–3 个简短步骤或核心收益，不塞小字。步骤卡片使用细边框和约 60% 透明度（约 40% 不透明）的局部磨砂底；不对整张背景加模糊层，也不加流程图大外框；圆角应平滑，文字与边框之间留足间距。Shorts、抖音和小红书竖图应缩短文案、放大主体并预留平台展示安全区；GitHub Social Preview 则在 2:1 画幅内优先呈现项目名称和核心价值。

每个 IP 必须有明确动作和职责：黑发人物讲解展示、拓拓执行动作、星比表达结果/方向/反馈；不得重复表达。竖向窄画幅角色数量过多时触发协调性警告。
