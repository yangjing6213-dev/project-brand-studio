# 构图与 shot list

先根据 `output-specs.md` 确认目标平台和画幅，再按每个比例单独规划封面构图；不再创建 1:1 方形主视觉。真实场景背景铺满画面，并根据项目用途选择合适的空间、道具和光线；不要固定切成“左侧留文案区、右侧产品场景”。文案允许覆盖在背景上，靠清晰对比与排版保持可读，不对整张背景加模糊层。多个版本沿用同一场景主题、品牌色和视觉气质，但针对每种画幅分别构图并生成匹配底图；不能裁切或拉伸一张底图来冒充其他比例。

## 主视觉风格构图

- **创作者桌面手写标题**：依据用户单独提供的人物素材安排人物在真实创作桌前操作电脑；标题采用大号手写/笔刷感排版，白色为主、黄色重点词可沿用参考风格；桌面设备和暖光帮助交代创作场景。人物素材与风格参考分开使用，不能从参考图复刻脸部。
- **演讲舞台大屏海报**：画面必须同时有主讲人物和清晰可见的大屏。镜头角度可随平台画幅调整，但不能让人物或屏幕消失、变成不易辨识的小元素。主标题置于屏幕外，以大字分层呈现；主标题以外的已确认文案排入屏幕中的留白/内容区。屏幕仅呈现确认过的文案，不生成额外可读 UI 字样。标题白色基础色与关键词强调色按 QA 确认结果排版。
- **明亮 SaaS 产品展示**：在明亮的真实产品演示/工作环境中，以显示器或设备上的产品画面为主视觉，文字说明与功能卡片形成清楚层级。只有使用用户提供的真实界面截图时才呈现真实可读界面；无截图时使用不带虚构文字的抽象界面块，功能卡片只使用已确认的产品事实。
- **沿用当前项目已有风格**：以当前项目已确认的品牌档案和已通过成品为依据。无可访问或已确认来源时停止该分支并让用户选择其他风格/补充参考，不能虚构“项目既有风格”。

这些风格只定义视觉方向，不改变平台尺寸、安全区和真实场景要求。参考图库中的原图仅用于风格抽象，不复制其人物身份、文字、商标、UI 或水印。

流程图按画幅取舍：宽版封面可放清晰的 3–4 步流程；竖版和小尺寸改为 2–3 个简短步骤或核心收益，不塞小字。步骤卡片使用细边框和约 60% 不透明度（约 40% 透明）的局部磨砂底；不对整张背景加模糊层，也不加流程图大外框；圆角应平滑，文字与边框之间留足间距。Shorts、抖音和小红书竖图应缩短文案、放大主体并预留平台展示安全区；GitHub Social Preview 则在 2:1 画幅内优先呈现项目名称和核心价值。

每个 IP 必须有明确动作和职责：黑发人物讲解展示、拓拓执行动作、星比表达结果/方向/反馈；不得重复表达。竖向窄画幅角色数量过多时触发协调性警告。
